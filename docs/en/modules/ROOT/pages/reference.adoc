== Build-time expression compiler

ExpressionCompiler.compile(binaryName, source) returns a fresh Java 25 class file
for literal text and templates whose evaluation parts are scalar literal and operator trees.
It supports null, boolean, string, integer and floating values, minus, not/! and empty,
including Long.MIN_VALUE and composite templates. Arithmetic +, -, *, / (div) and
% (mod), logical operators, conditional ?:, scalar comparisons, concatenation += and
sequences are emitted directly. Standalone root identifiers and property navigation are
also supported, including resolved arithmetic/comparisons and inline member calls.
Assignments compile over supported root/property targets.
Bare callables, mapped functions and constructors are rejected in this slice.
List, set and map literals emit fresh mutable JDK collections, preserving order, nulls
and duplicate handling. Their elements can include captured root/property values and
supported operator/collection trees.
Syntax, unsupported nodes and Class-File size failures raise ELException; invalid
qualified binary names raise IllegalArgumentException. The caller owns output placement.

[source,java]
----
byte[] bytes = ExpressionCompiler.compile("example.generated.Answer", "${42}");
Files.write(output.resolve("example/generated/Answer.class"), bytes);
----

The generated public class extends CompiledValueExpression in peano-api and has
a public constructor receiving the expected result Class:

[source,java]
----
ValueExpression answer = new example.generated.Answer(Long.class);
Long value = answer.getValue(context);
----

The application module requires io.vidocq.peano.api. Neither peano-core nor
peano-compiler is required by the emitted class; the caller supplies an ELContext.
The compiler itself is build tooling with internal core/API dependencies and
java.compiler for name validation, without external tooling dependencies.
Only the compiler can read the core syntax package through its qualified export.
Generated subclasses evaluate directly; the shared API base owns conversion,
events, parsed identity, read-only metadata and serialization.
Identity keys are opaque compiler output and must represent normalized parsed form;
bindingIdentity contributes captured bindings when subclasses need them.

Emitted serialization UIDs fingerprint normalized structure and the emission-schema
version. Equivalent templates remain compatible across regenerated classes; changed
expression bodies reject old streams with InvalidClassException. Artifacts from the
initial fixed-UID prototype and pre-v3 emission rules must be regenerated. Each nonempty
parsed text literal has a distinct private final instance String to preserve conversion
effects at equality's identity shortcut, including between captured expression instances.
Constructors initialize those values; serialization preserves their expression-local scope.
Unary getType reevaluates the body,
preserving caller conversion effects. Arithmetic evaluates both operands before math
coercion and preserves the interpreter's Long/Double domains and error causes for the
supported scalar trees.

Logical and/&&, or/|| and conditional ?: compile to lazy branches. Evaluated operands use the caller's
boolean conversion; discarded operands remain inactive. Numeric overflow raises
ELException with a NumberFormatException cause only if its literal is evaluated.
Operator getType retains the same operand and conversion effects.
Conditional results can be null or select different scalar types. Numeric operations
promote from the actual selected values; empty inspects the actual selected value.
Scalar comparison preserves reference/null shortcuts, numeric/boolean/text precedence,
NaN behavior and guarded conversion errors. Concatenation evaluates both operands before
String conversion. Sequences evaluate the left operand before returning the right value.

Standalone identifiers extend the API CompiledRootValueExpression protocol.
Their public Class constructor uses dynamic resolver lookup without VariableMapper
capture. Their public ELContext/Class constructor captures the root binding at creation;
changing the mapper later does not remap that expression. No context is retained.
Lambda arguments take precedence over captured bindings. Root metadata, writes and
references delegate to the captured ValueExpression or resolver without reading a getter.
Root resolver writes do not coerce against a declared property type. Import lookup,
resolution flags, error causes, evaluation events and binding serialization are preserved.
Captured ValueExpressions and their payloads must be serializable; their implementation
modules must remain available when restoring them.
Generated root classes run with core and compiler absent in both reflection modes;
resolver implementations retain responsibility for their own member access.

Standalone property trees extend CompiledPropertyValueExpression. Both constructor
forms are available; the context form captures each distinct root/key binding once.
Generated evaluation short-circuits null bases and keys. Metadata and writes reject
null locations and evaluate parent/key expressions without reading the final getter.
Property writes consult the resolver's type before caller conversion and assignment.
Nested/indexed paths and scalar computed keys are supported. Resolver flags, captured
binding identity and serialization follow the root protocol's boundaries.
Collection literals support nested structures and content equality; empty checks actual
contents. Ordered comparisons use Comparable fallback or raise ELException when unsupported.
Captured values also compose in logical/conditional bodies, concat, sequences and templates.
Readonly bodies return no location; composite metadata remains String without getter reads.
Empty checks runtime primitive/reference array length through the documented java.base exception.
Resolved numeric operands support all EL arithmetic domains: BigDecimal and BigInteger
promotion, floating/integral operations, HALF_UP decimal division and modulo rules.
Unary minus preserves Byte, Short, Integer, Long, Float, Double, BigInteger and BigDecimal
types. Both operands are read before numeric conversion; null becomes Long zero, and
math guards preserve ELException or wrap other RuntimeExceptions with their cause.
Resolved comparisons retain BigDecimal/floating/BigInteger/integral/boolean/enum/string
precedence, reference/null shortcuts, scale-sensitive decimal equality and NaN ordering.
Equality passes raw RHS conversion results to equals. Enum conversion targets the
declaring class; Object.equals and Comparable callbacks remain available as fallbacks.
Inline member calls evaluate base/key first, convert a non-null key to String, then
evaluate arguments left to right. Null bases/keys discard arguments. Invocation uses
the supplied resolver with inferred parameter types and retains flags, claimed nulls
and exception causes. No direct member reflection or bare-method fallback is added;
resolver implementations own their access policy. Call bodies are readonly and their
getType evaluates the raw result; calls can also be parents in property navigation.
Assignment prepares the lvalue before evaluating its RHS. Property and alias locations
are frozen once; readonly/lambda/invalid/null targets fail before RHS effects. Namespace
resolution and declared property conversion happen when writing. The expression returns
the original RHS, retains readonly metadata and reevaluates its write in getType.
Temporary precompiled writers add no expression fields or serialized context state.

== Legacy property-editor boundary

Core, API, processor and compiler do not require java.desktop. Optional artifact
`io.vidocq.peano:peano-beans-compat` (module `io.vidocq.peano.beans.compat`) enables
PropertyEditorManager discovery. Build it with `./mvnw -ntp -Pbeans-compat install`
and include its jar on the runtime module path; service binding can resolve java.desktop.
Without that artifact, nonempty text without a converter raises ELException and empty
text to an otherwise unsupported reference target returns null.

The API TypeConversionProvider service runs after built-in coercions and before the
unsupported-target empty-text fallback. Providers run by descending priority and class
name; the editor provider has lowest priority. Context-local ELResolver converters win.
Factory and context conversion both use installed providers. Each editor conversion
obtains a fresh editor, observes registry updates and returns successful empty-text results.
Failed empty text returns null; invalid nonempty text raises ELException with its cause.
Editor packages instantiated by the JDK may need exports qualified to java.desktop.
Installing the optional artifact enables registry compatibility in both reflection modes.

An application that already uses java.beans can explicitly require java.desktop
and add its own ELResolver converter to the context. Construct an editor for each
conversion, claim the operation with setPropertyResolved(true), call setAsText,
then return the typed getValue result. If an editor fails on empty text, return null;
on other invalid text, raise ELException. This explicit integration is verified in
a closed application module under reflection-denial mode.

ELContext conversion can use that resolver; ExpressionFactory.coerceToType has no
caller context and does not inherit context-local converters. Use the optional artifact
when automatic registry discovery is needed for factory conversion.

See https://jakarta.ee/specifications/expression-language/6.0/jakarta-expression-language-spec-6.0[EL 6.0 sections 1.25 and 1.25.9].

== Reflection policy

The system property peano.reflection accepts allow (default) or deny. Other values
raise ELException. Set it before application startup.
In deny mode, Peano's member fallback rejects ungenerated bean/record access, static
fields and methods, constructors and reflective method metadata, naming the target type.
Custom resolvers and generated tables run first. Direct map/list/resource-bundle/array
properties and collection pipelines remain available.
Restoring serialized captured functions requires allow, including functions whose
invocation has a generated table: their Method descriptor is restored by lookup.
The setting governs Peano's fallback; application resolvers and API import handling
retain their own implementation responsibility.

== Java functional-interface conversion

Peano includes statically compiled adapters for all 43 java.util.function interfaces
and java.lang.Runnable, java.util.concurrent.Callable and java.util.Comparator
(EL 6.0 section 1.25.8). Generic contracts use erasure; primitive specializations
coerce lambda results to their descriptor's return type. Consumers and Runnable
discard results. Default methods retain Java behavior.
ELContext conversion preserves custom converters for both the target and result;
ExpressionFactory.coerceToType retains the lambda's captured context and uses intrinsic
result conversion. These adapters work as typed Java callbacks and as generated method
arguments in reflection-denial mode. EL member navigation on adapters retains the
normal fallback policy.

== Official TCK tooling

The unpublished peano-tck runner uses
`jakarta.tck:jakarta-expression-language-tck:6.0.1` from the official distribution
and `jakarta.tck:sigtest-maven-plugin:2.3` as its signature-test runtime, matching
the distribution's embedded metadata. Both are test dependencies behind
`-Ptck,tck-official`; none ships with peano-core.
The signature runtime's Maven tooling dependencies remain test-only.
Local installation uses a minimal POM to avoid importing the TCK's release-build parent.

The upstream suite is non-modular. Its runner uses the classpath and selects
Peano via the Jakarta ExpressionFactory property, an exception confined to this
test harness. Independent named-consumer tests enforce the production module boundaries.

== Annotation processor selection (implemented)

Selected application interfaces generate lambda adapters when annotated with
java.lang.FunctionalInterface and non-sealed (EL 6.0 section 1.25.8).
Use the same ELAccessible annotation or explicit-types option and register the emitted
AccessorProvider fragment. Child interfaces require their own selection. Generic
interface signatures use erasure; generic functional methods receive diagnostics.

Annotated and explicit roots also select accessible source descendants in the current
compilation, including nested and later-round declarations. Each type has its own
provider and registration fragment. Register every required provider in module-info.java.
Binary descendants are not inferred; unselected private descendants are skipped.
This family selection depends on compilation roots and is not build-tool isolating
incremental processing.

* `io.vidocq.peano.annotation.ELAccessible`: SOURCE-retained TYPE annotation on an owned class or record.
* `-Apeano.accessorTypes=pkg.Type,pkg.Other`: comma-separated owned type names, including models produced by another processor in a later round.
* Generated provider: `pkg.Type__PeanoAccessors` (nested binary names retain their dollar separators).
* Registration fragment: `META-INF/peano/accessor-providers/pkg.Type__PeanoAccessors.txt`.

Put peano-processor, peano-api and jakarta.el-api on javac's processor module path.
Only peano-api and peano-core are needed at application runtime.
The processor uses java.compiler and the internal API, with no external tooling dependency.
AccessorTable.getMethodReference supplies generated metadata. MethodDescriptor snapshots
erased signatures and runtime annotations; MethodSelection chooses overloads from those
constants, using the evaluation context for coercion probes.
