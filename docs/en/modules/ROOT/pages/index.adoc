= Peano
:description: Jakarta Expression Language 6.0 implementation — zero third-party dependency, native Java Modules, build-time accessors and compiled expressions. P5 implementation in progress.

[.text-center]
image::peano-logo.png[Peano,300,role=module-logo]

[.lead]
Peano is the Jakarta Expression Language 6.0 implementation of the Vidocq ecosystem, in pure Java 25: zero third-party dependency (only the `jakarta.el` spec jar), strict Java Modules, and — like every Vidocq brick — property accessors and expressions generated at build time where others reflect at run time.

[IMPORTANT]
====
Peano is **in development (P5)**: grammar, operators, coercions and the `ExpressionFactory`
provider are implemented. Resolver-backed value expressions now navigate models,
capture variables and expose get/set/metadata with imports and static fields.
Functions, method expressions, method references and assignments are implemented.
Lambda execution, list/set/map construction and lazy chapter 2 collection
pipelines are implemented. Java functional-interface adaptation remains planned; known API limitations
are recorded in BUG.md.
Evaluation listeners and expression serialization are implemented.
This documentation describes the intended `{project-version}` development line; every page states what exists today.
====

== Origin of the name

Giuseppe Peano (1858–1932), the Turin logician who gave mathematics a rigorous formal notation — the `∈` symbol, the axioms of arithmetic that bear his name, the _Formulario mathematico_. See https://en.wikipedia.org/wiki/Giuseppe_Peano[the Wikipedia article].

Peano wanted expressions written in a notation without ambiguity, so that evaluating them became a mechanical act. That is the whole job of an Expression Language engine: parse `${order.total * 1.2}` into one unambiguous tree, then evaluate it the same way every time.

== Three identifying traits

. **Zero third-party dependency** — the `jakarta.el` spec jar only. No Expressly, no Jakarta EL reference implementation, no parser generator: a hand-written lexer and recursive-descent parser.
. **Standard bootstrap** — `ExpressionFactory.newInstance()` and `ELProcessor` find Peano through the spec's `ServiceLoader` lookup. No Peano-specific API to learn.
. **Codegen-first** — accessor tables generated by an annotation processor replace reflective bean introspection, and expressions known at build time are compiled with the Class-File API. Reflection remains only as a documented, switchable fallback.

== Position in the ecosystem

Peano is a foundational brick: it depends on no other Vidocq module. Ibarra (Jakarta Pages 4.0) uses it to evaluate page expressions and compiles page expressions with it at build time; a future `vauban-el` module of Vauban will expose CDI `@Named` beans to it through the standard `ELResolver` extension point.
